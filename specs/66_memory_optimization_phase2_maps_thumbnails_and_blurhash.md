# Specification 66: Runtime Memory Optimization Phase 2 — Maps, Thumbnail Downsizing & BlurHash Cache Optimization

**Status:** Implemented

## 1. Overview & Problem Statement

Following the Phase 1 image cache and grid virtualization fixes ([Spec 65](file:///Users/davidtiagoconceicao/Developer/image-feed-app/specs/65_memory_optimization_phase1_caches_grids_and_scopes.md)), Phase 2 targets three major secondary contributors to native and managed heap consumption across Android (`androidApp`), iOS/macOS (`iosApp`), and Shared KMP (`:core:model`):

1. **Heavy Interactive Map Engines for Static Read-Only Location Previews**:
   - **Android ([`PhotoDetailsScreen.kt` L1183-L1211](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L1183-L1211))**: The 180dp location card embeds a full interactive `GoogleMap` composable with all gestures disabled (`scrollGesturesEnabled = false`, `zoomGesturesEnabled = false`, etc.), initializing a full OpenGL/Vulkan vector tile renderer and tile cache (~30–60 MB native heap). Furthermore, `MapStyleOptions.loadRawResourceStyle(context, R.raw.map_style_dark)` ([L1189-L1192](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L1189-L1192)) re-reads and parses the raw JSON style resource on every recomposition without `remember`.
   - **iOS/macOS ([`PhotoDetailsView.swift` L910-L936](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/PhotoDetailsView.swift#L910-L936))**: `MapCardView` embeds a live `MapKit.Map(position: $position)` view for a 150pt non-interactive preview card, allocating Metal vector map rendering surfaces and tile caches (~40–80 MB on iOS/macOS) every time photo details with coordinates are opened.

2. **Oversized `urls.regular` (1080px) Loads & Duplicate `&w=` Query Parameters**:
   - [`PhotoUrls`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/model/src/commonMain/kotlin/com/example/imagefeed/model/Photo.kt#L30-L37) in `:core:model` lacks a standardized `getOptimalUrl(targetWidthPx: Int, quality: Int = 80): String` helper, leading screens to either hardcode `urls.regular` (1080px wide) for small cards / blurred headers or concatenate `&w=` parameters onto `urls.small` (which already contains `&w=400&q=80` from Unsplash's API, producing malformed duplicate query parameters `&w=400...&w=...`):
     - **Android oversized `urls.regular` loads**: [`CollectionRowCard` (`SearchScreen.kt` L799)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/SearchScreen.kt#L799), [`CollectionRowLayout` (`UserProfileScreen.kt` L876)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/UserProfileScreen.kt#L876), and [`CollectionDetailHeader` (`CollectionDetailScreen.kt` L318)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionDetailScreen.kt#L318) (which applies `.blur(20.dp)` to a 1080px image when a 400px `urls.small` image is visually indistinguishable under a 20dp blur).
     - **iOS oversized `urls.regular` loads**: [`CollectionCardView` (`SearchView.swift` L411)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/SearchView.swift#L411) and [`GridCollectionsList` (`UserProfileView.swift` L487)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/UserProfileView.swift#L487) load `coverPhoto.urls.regular` into a 180pt-tall card, and [`CollectionDetailView.swift` L104](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/CollectionDetailView.swift#L104) loads `coverPhoto.urls.regular` into a `.blur(radius: 12)` header backdrop.
     - **Duplicate `&w=` query params on `urls.small`**: [`CollectionMosaicCard` (`CollectionsFeedScreen.kt` L358, L375, L395, L412)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionsFeedScreen.kt#L358-L413) and [`CollectionMosaicCard` (`CollectionsFeedView.swift` L190, L198, L213, L221)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/CollectionsFeedView.swift#L190-L221) append `&w=...&q=80&auto=format` onto `urls.small` instead of `urls.raw`.

3. **Per-Recomposition `BitmapPainter` Wrapping, Unquantized BlurHash Heights & Entry-Count Cache Sizing**:
   - [`rememberBlurHashPlaceholder`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/util/BlurHashDecoder.kt#L263-L285) returns `Bitmap?`, forcing all 8 Android call sites ([`FeedScreen.kt` L321/L335, L468/L500](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/FeedScreen.kt#L321-L336), [`CollectionsFeedScreen.kt` L276/L324, L360/L378, L397/L415](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionsFeedScreen.kt#L276-L416), [`CollectionDetailScreen.kt` L309/L329](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionDetailScreen.kt#L309-L330), [`SearchScreen.kt` L781/L800](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/SearchScreen.kt#L781-L801), and [`PhotoDetailsScreen.kt` L381/L395](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L381-L396)) to execute `placeholderBitmap?.let { BitmapPainter(it.asImageBitmap()) }` inline in composition without `remember`, allocating a new `AndroidImageBitmap` and `BitmapPainter` wrapper on every recomposition. Additionally, [`RelatedCollectionCard` (`CollectionDetailScreen.kt` L491)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionDetailScreen.kt#L491) and [`CollectionRowLayout` (`UserProfileScreen.kt` L876)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/UserProfileScreen.kt#L876) omit BlurHash placeholders altogether.
   - Dynamic placeholder heights in [`FeedScreen.kt` L310-L317](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/FeedScreen.kt#L310-L317) and [`PhotoDetailsScreen.kt` L373-L379](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L373-L379) use exact integer division `(32 / aspectRatio).toInt()`, producing dozens of distinct height keys (`1..128`) and fragmenting cache reuse when identical BlurHash strings appear in fixed-ratio cards vs aspect-ratio cards.
   - [`BlurHashDecoder.cache`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/util/BlurHashDecoder.kt#L25-L28) is bounded by entry count (`DEFAULT_CACHE_SIZE = 256`) without overriding `sizeOf(key, value)` to account for actual bitmap byte allocation (`allocationByteCount`), allowing large decoded dimensions (up to `MAX_DIMENSION = 512`, i.e., 1 MB per bitmap) to consume disproportionate heap.

## 2. Technical Design

### A. Lightweight Static Map Rendering on Android & iOS/macOS
1. **Android Google Maps Lite Mode & Remembered Style ([`PhotoDetailsScreen.kt` L1183-L1211](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L1183-L1211))**:
   - Pass `googleMapOptionsFactory = { GoogleMapOptions().liteMode(true) }` to `GoogleMap(...)` so Play Services renders a lightweight static bitmap tile instead of instantiating a full interactive vector GL engine.
   - Hoist and `remember(context)` the dark map style: `val mapStyleOptions = remember(context) { MapStyleOptions.loadRawResourceStyle(context, R.raw.map_style_dark) }` and `remember(mapStyleOptions) { MapProperties(mapStyleOptions = mapStyleOptions) }`, plus a top-level/remembered `MapUiSettings` instance.
2. **iOS/macOS `MKMapSnapshotter` Static Snapshot ([`PhotoDetailsView.swift` L910-L936](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/PhotoDetailsView.swift#L910-L936))**:
   - Replace `Map(position: $position)` inside `MapCardView` with an asynchronous `MKMapSnapshotter` snapshot cached in `ImageMemoryCache` (from [Spec 65](file:///Users/davidtiagoconceicao/Developer/image-feed-app/specs/65_memory_optimization_phase1_caches_grids_and_scopes.md)) keyed by rounded coordinate + size + colorScheme:
     - Configure `MKMapSnapshotter.Options` with `region`, `size = CGSize(width: width, height: 150)`, and display scale (`UIScreen.main.scale` on iOS, `NSScreen.main?.backingScaleFactor` on macOS).
     - Draw a pin/marker indicator at `snapshot.point(for: coordinate)` into the rendered image context so the visual appearance matches the previous `Marker`, and cancel the `MKMapSnapshotter` in `.task(id:)` teardown if the sheet closes before completion.

### B. Standardized `PhotoUrls.getOptimalUrl` & Elimination of Oversized / Duplicate-Param Requests
1. **Shared Helper on [`PhotoUrls` (`Photo.kt` L30-L37)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/model/src/commonMain/kotlin/com/example/imagefeed/model/Photo.kt#L30-L37)**:
   - Add `fun getOptimalUrl(targetWidthPx: Int, quality: Int = 80): String` and `fun getOptimalUrl(targetWidthPx: Int): String = getOptimalUrl(targetWidthPx, 80)` on `PhotoUrls`:
     - Clamps `targetWidthPx` to sensible bounds (e.g. `targetWidthPx.coerceIn(64, 2400)`), strips any existing `&w=`, `&q=`, or `&auto=` overrides if accidentally called on a non-raw URL, and appends `"&w=$clampedWidth&q=$quality&auto=format"` onto `raw` (using `?` if `raw` lacks a query string, preserving `ixid` and all existing query parameters on `raw`).
     - Providing both the 1-parameter and 2-parameter overloads in Kotlin commonMain ensures that Swift/Objective-C callers can invoke `urls.getOptimalUrl(targetWidthPx: itemWidthPx)` idiomatically without being forced to explicitly pass `quality: 80` (as Kotlin default arguments are not exported to Objective-C headers).
2. **Fix Duplicate `&w=` Appends**:
   - In [`CollectionsFeedScreen.kt` L296-L305, L322, L358, L375, L395, L412](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionsFeedScreen.kt#L296-L413) and [`CollectionsFeedView.swift` L167, L190, L198, L213, L221](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/CollectionsFeedView.swift#L167-L221), replace `urls.small + "&w=..."` and manual `urls.raw + "&w=..."` with `urls.getOptimalUrl(targetWidthPx = ...)` (and ensure `CollectionsFeedView.swift` multiplies `width` and `sideWidth` by display scale `UIScreen.main.scale` / `backingScaleFactor` per **Core Invariant 4**).
3. **Downsize Oversized `urls.regular` Card & Blurred Header Requests**:
   - **Android**:
     - [`CollectionRowCard` (`SearchScreen.kt` L799)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/SearchScreen.kt#L799) & [`CollectionRowLayout` (`UserProfileScreen.kt` L876)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/UserProfileScreen.kt#L876): use `coverPhoto.urls.getOptimalUrl(cardWidthPx)` (with `remember(coverPhoto.id, cardWidthPx)` per [Spec 61](file:///Users/davidtiagoconceicao/Developer/image-feed-app/specs/61_android_media_card_hot_path_optimization.md)).
     - [`CollectionDetailHeader` (`CollectionDetailScreen.kt` L318)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionDetailScreen.kt#L318): use `collection.coverPhoto?.urls?.small` (400px) instead of `urls.regular` (1080px) for the `.blur(20.dp)` background backdrop.
     - [`UserRowCard` (`SearchScreen.kt` L948)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/SearchScreen.kt#L948): use `user.profileImage.medium` (64px) instead of `user.profileImage.large` (128px) for the 54dp avatar (matching iOS [`UserCardView` (`SearchView.swift` L449)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/SearchView.swift#L449)).
     - Standardize [`FeedScreen.kt` L332](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/FeedScreen.kt#L332) and [`PhotoDetailsScreen.kt` L392](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L392) to use `photo.urls.getOptimalUrl(...)`.
   - **iOS/macOS**:
     - [`CollectionCardView` (`SearchView.swift` L411)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/SearchView.swift#L411) & [`GridCollectionsList` (`UserProfileView.swift` L487)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/UserProfileView.swift#L487): use `coverPhoto.urls.getOptimalUrl(targetWidthPx: itemWidthPx, quality: 80)` instead of `urls.regular`.
     - [`CollectionDetailView.swift` L104](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/CollectionDetailView.swift#L104): use `coverPhoto.urls.small` (400px) instead of `coverPhoto.urls.regular` (1080px) for the `.blur(radius: 12)` parallax header backdrop (matching Android `CollectionDetailHeader`).
     - Standardize [`PhotoCard` (`ContentView.swift` L636)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/ContentView.swift#L636), [`SearchPhotoGridCard` (`SearchView.swift` L275)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/SearchView.swift#L275), [`CollectionPhotoGridCard` (`CollectionDetailView.swift` L319)](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/CollectionDetailView.swift#L319), [`UserProfileView.swift` L414](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/UserProfileView.swift#L414), and [`PhotoDetailsView.swift` L238, L316](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/PhotoDetailsView.swift#L238) to call `photo.urls.getOptimalUrl(targetWidthPx: ..., quality: ...)` (using actual display scale in `PhotoDetailsView.swift` instead of hardcoded `* 2` per **Core Invariant 4**).

### C. Remembered `BitmapPainter?`, Quantized Aspect Buckets & Byte-Bounded `BlurHashDecoder`
1. **Return Remembered `BitmapPainter?` from [`rememberBlurHashPlaceholder`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/util/BlurHashDecoder.kt#L263-L285)**:
   - Update `rememberBlurHashPlaceholder` (or provide `rememberBlurHashPainter(blurHash: String?, width: Int, height: Int, punch: Float = 1.0f): BitmapPainter?` and migrate all call sites) so `remember(placeholderBitmap) { placeholderBitmap?.let { BitmapPainter(it.asImageBitmap()) } }` is cached once per decoded `Bitmap` instead of re-allocating on every recomposition.
   - Update all Android call sites ([`FeedScreen.kt` L321, L468](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/FeedScreen.kt#L321), [`CollectionsFeedScreen.kt` L276, L360, L397](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionsFeedScreen.kt#L276), [`CollectionDetailScreen.kt` L309, L495](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/CollectionDetailScreen.kt#L309), [`SearchScreen.kt` L781](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/SearchScreen.kt#L781), [`UserProfileScreen.kt` L876](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/UserProfileScreen.kt#L876), and [`PhotoDetailsScreen.kt` L381](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt#L381)) to consume the remembered `BitmapPainter?` directly.
2. **Quantize Placeholder Heights to Discrete Buckets**:
   - Add a helper `BlurHashDecoder.quantizeHeight(width: Int, aspectRatio: Float): Int` that rounds computed heights to multiples of 4 pixels (clamped to `BLURHASH_PLACEHOLDER_MIN_HEIGHT..BLURHASH_PLACEHOLDER_MAX_HEIGHT`, e.g., `((rawHeight + 2) / 4 * 4).coerceIn(4, 128)`), collapsing near-identical aspect ratios into a small set of canonical dimensions (`16, 20, 24, 28, 32, 36, 40, 48...`) and maximizing LRU cache hits across Feed, Search, Profile, and Details.
3. **Byte-Size-Bounded `LruCache` in [`BlurHashDecoder.kt`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/util/BlurHashDecoder.kt#L25-L50)**:
   - Replace the entry-count `LruCache<String, Bitmap>(256)` with a byte-bounded `LruCache<String, Bitmap>(DEFAULT_CACHE_MAX_BYTES)` (e.g. `1024 * 1024` = 1 MB default max size) overriding `sizeOf(key: String, value: Bitmap): Int = value.allocationByteCount.coerceAtLeast(width * height * 4)` (with a fallback calculation `value.width * value.height * 4` when `allocationByteCount` is 0 in JVM unit tests using mocked/stubbed `Bitmap`s).

## 4. Acceptance Criteria

- [x] `PhotoDetailsScreen.kt` configures `GoogleMap` with `liteMode(true)` and remembers `MapStyleOptions`, `MapProperties`, and `MapUiSettings`.
- [x] `MapCardView` in `PhotoDetailsView.swift` replaces live `MapKit.Map` with a cached `MKMapSnapshotter` static image with a pin overlay.
- [x] `PhotoUrls.getOptimalUrl(targetWidthPx, quality)` and single-parameter `getOptimalUrl(targetWidthPx)` overload are implemented in `:core:model` and preserve `ixid`.
- [x] Duplicate `&w=` query parameters on `urls.small` in `CollectionsFeedScreen.kt` and `CollectionsFeedView.swift` are eliminated, and oversized `urls.regular` loads in small collection/preview cards across Android and iOS are replaced.
- [x] `rememberBlurHashPlaceholder` returns a remembered `BitmapPainter?` directly across all Android call sites; zero inline `BitmapPainter(it.asImageBitmap())` calls remain in screen composables.
- [x] `BlurHashDecoder` quantizes placeholder heights to discrete buckets and bounds its `LruCache` by byte size (`sizeOf` using `allocationByteCount` with unit-test-safe fallback).
- [x] Zero compiler warnings, zero dead code, and all Android, iOS, and KMP unit tests pass.
