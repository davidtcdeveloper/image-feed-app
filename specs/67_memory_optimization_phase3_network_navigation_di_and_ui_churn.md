# Specification 67: Runtime Memory Optimization Phase 3 — Network Buffering, Navigation Hygiene, DI Scoping & UI Frame Churn

**Status:** Approved

## 1. Overview & Problem Statement

Building on Phase 1 ([Spec 65](file:///Users/davidtiagoconceicao/Developer/image-feed-app/specs/65_memory_optimization_phase1_caches_grids_and_scopes.md)) and Phase 2 ([Spec 66](file:///Users/davidtiagoconceicao/Developer/image-feed-app/specs/66_memory_optimization_phase2_maps_thumbnails_and_blurhash.md)), Phase 3 addresses structural memory retention and high-frequency allocation churn across the Ktor networking layer (`:core:network`), Metro DI modules (`:feature:*`), Navigation 3 / SwiftUI navigation stacks, and 60/120Hz scroll and animation paths:

1. **Unconditional Full-Payload HTTP Logging & Redundant JSON Allocation in `:core:network`**:
   - [`createUnsplashHttpClient`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L21-L60) installs Ktor's `Logging` plugin with unconditional `level = LogLevel.ALL` ([L34](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L34)). Under `LogLevel.ALL`, Ktor reads and buffers the entire HTTP response body into an in-memory `String` before forwarding the byte stream to `kotlinx.serialization`, doubling peak memory for every feed, search, and detail JSON payload even in release builds.
   - `ContentNegotiation` configures `Json` with `prettyPrint = true` ([L27](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L27)), and `HttpResponseValidator` ([L44](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L44)) calls `Json.parseToJsonElement(errorText)` on the default `Json` companion rather than reusing a single shared `Json` instance.

   - **Android Search ViewModel Proliferation & Unbounded Detail Backstacks**:
     - [`NavigationSections.kt` L134](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/navigation/NavigationSections.kt#L134) keys `UnifiedSearchViewModel` as `viewModel(key = "search_${key.query}")`, retaining a separate `UnifiedSearchViewModel` (and its loaded photo/collection/user lists) in the `NavEntry` store for every distinct tag query navigated to via `AppRoute.Search(query = tag)` ([L177](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/navigation/NavigationSections.kt#L177)) if entries remain on the stack.

## 2. Technical Design

### A. Ktor `HttpClient` Memory & JSON Hardening ([`HttpClientFactory.kt`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt))
1. Extract a single top-level `internal val unsplashJson = Json { ignoreUnknownKeys = true; prettyPrint = false; isLenient = true }`.
2. Pass `unsplashJson` to `install(ContentNegotiation) { json(unsplashJson) }` and reuse `unsplashJson.parseToJsonElement(errorText)` inside `HttpResponseValidator` ([L44](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L44)).
3. Change `Logging` `level` ([L34](file:///Users/davidtiagoconceicao/Developer/image-feed-app/core/network/src/commonMain/kotlin/com/example/imagefeed/core/network/HttpClientFactory.kt#L34)) from `LogLevel.ALL` to `LogLevel.NONE` (or `LogLevel.INFO` / `LogLevel.HEADERS` only when a debug flag is enabled, never buffering response bodies).

### B. Navigation Stack & State Retention Hygiene
1. **iOS Hero Overlay Cleanup ([`ContentView.swift` L339-L362, L375-L398, L514-L522](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/ContentView.swift#L339-L522))**:
   - Preserve `selectedPhotoForHero = nil` in `onUserSelect` and `onTagSelect` ([L348-L359](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/ContentView.swift#L348-L359)), and additionally clear `selectedPhotoForHero = nil` inside `handleShake()` ([L518-L521](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/ContentView.swift#L518-L521)), the Search toolbar button action ([L376, L389](file:///Users/davidtiagoconceicao/Developer/image-feed-app/iosApp/iosApp/ContentView.swift#L376)), and an `.onChange(of: activePath.wrappedValue.count)` observer whenever `count > 0` so `selectedPhotoForHero` can never remain mounted behind a pushed destination.
2. **Android Navigation Backstack Bounds & Search ViewModel Scoping**:
   - In [`NavigationSections.kt` L128-L136](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/navigation/NavigationSections.kt#L128-L136), use a stable key (`key = if (key.query.isEmpty()) "search_root" else "search_tag_${key.query}"`) and in [`Navigator.navigate`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/androidApp/src/main/java/com/example/imagefeed/android/navigation/Navigator.kt#L13-L30):
     - Deduplicate existing identical routes in the active stack (pop-up-to or move-to-top when navigating to a `UserProfile`, `CollectionDetails`, `PhotoDetails`, or `Search(query)` already in `currentStack`) and enforce a maximum detail chain depth (e.g., `MAX_BACKSTACK_DEPTH = 8`, evicting the oldest non-root detail entry when exceeded) to prevent unbounded `ViewModelStore` accumulation during deep browsing loops.
     - When switching top-level tabs via the bottom bar (`route == matchingTopLevel` with empty query), optionally trim deep sub-routes on inactive non-home stacks or rely on the bounded depth cap.
3. **Shared State Pagination Caps & Tab Memory Hygiene**:
   - In [`UnifiedSearchViewModel`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/feature/search/src/commonMain/kotlin/com/example/imagefeed/presentation/search/UnifiedSearchViewModel.kt) and [`UserProfileViewModel`](file:///Users/davidtiagoconceicao/Developer/image-feed-app/feature/profile/src/commonMain/kotlin/com/example/imagefeed/presentation/profile/UserProfileViewModel.kt), cap in-memory list retention for inactive tabs (e.g., when switching `activeTab`, trim inactive tab lists to the first page `take(20)` and reset their page counter to `1` if they exceed 1 page, so switching tabs frees multi-page lists while keeping instant first-page tab switching).

1. **Guarded Property Updates in All 6 Swift `@Observable` ViewModels**:

## 4. Acceptance Criteria

- [ ] `HttpClientFactory.kt` uses `LogLevel.NONE` (or headers-only in debug), sets `prettyPrint = false`, and reuses a single `Json` instance in `ContentNegotiation` and `HttpResponseValidator`.
- [ ] `ContentView.swift` clears `selectedPhotoForHero = nil` across all navigation paths (`onUserSelect`, `onTagSelect`, `handleShake`, and any `activePath` push).
- [ ] Android `Navigator` / `NavigationSections` prevents unbounded detail backstack growth and avoids leaking distinct `UnifiedSearchViewModel` instances per query; inactive tab lists in `UnifiedSearchState` and `UserProfileState` are bounded on tab switch.
- [ ] All 5 feature repository `@Provides` functions (`FeedModule`, `CollectionsModule`, `SearchModule`, `ProfileModule`, `PhotoDetailsModule`) are annotated with `@SingleIn(AppScope::class)` without leaking DI annotations into Objective-C headers.
- [ ] All 6 Swift `@Observable` ViewModels guard property/array assignments against unchanged values.
- [ ] `ContentView.handleScroll` guards `activeCapsuleMinimized` mutations and avoids per-frame `Task` allocations.
- [ ] `AdaptiveLayoutHelper` provides $O(1)$ item indices for masonry columns, removing all `firstIndex(where:)` scans in `CollectionDetailView.swift`, `SearchView.swift`, and `UserProfileView.swift` without breaking `ContentView.swift` or `CollectionsFeedView.swift`.
- [ ] Shimmer skeletons share a single `InfiniteTransition` and chart list transformations + `Canvas` `Path`/`Brush` allocations are remembered/cached (verified as fulfilled by [Spec 60](60_android_shimmer_skeleton_rendering_optimization.md) and [Spec 63](63_android_photo_details_and_chart_rendering_optimization.md)).
- [ ] Zero compiler warnings, zero dead code, and both Android and iOS builds + unit tests pass.
