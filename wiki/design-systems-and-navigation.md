# Design Systems & Navigation

Both platform shells remain thin, declarative view layers rendering shared MVI state using platform-idiomatic design languages.

---

## 1. Android: Material 3 Expressive & Jetpack Navigation 3

### Navigation Architecture
* **Type-Safe Routes**: [`AppRoute`](../androidApp/src/main/java/com/example/imagefeed/android/navigation/Routes.kt) defines sealed `NavKey` destinations (`Feed`, `Collections`, `CollectionDetails(collectionId)`, `Favorites`, `Search(query)`, `PhotoDetails(photoId)`, `UserProfile(username)`).
* **Multiple Backstacks & Depth Bound**: [`Navigator.kt`](../androidApp/src/main/java/com/example/imagefeed/android/navigation/Navigator.kt) manages per-tab backstacks (`TOP_LEVEL_DESTINATIONS`: Photos, Collections, Favorites, Search), preserves scroll/state on tab switching, trims sub-route stack depth to `MAX_BACKSTACK_DEPTH = 8`, and emits reselection events (`reselectEvents`) for scroll-to-top behavior.
* **Resumed Navigation Guard & In-App Profile Routing**: [`NavigationSections.kt`](../androidApp/src/main/java/com/example/imagefeed/android/navigation/NavigationSections.kt) wraps navigation callbacks in `dropUnlessResumed` / `dropUnlessResumedWithArg`, routes all photographer and curator taps across Feed, Collections, Collection Details, Favorites, Search, and Photo Details in-app to `AppRoute.UserProfile(username)` (preserving explicit UTM referral browser intents strictly on "Open in Web" actions), and supplies `ProvideAppSharedTransition` + `ProvidePaneWidth` at every pane boundary.
* **Adaptive Scenes & Pane-Width Awareness**: [`AdaptiveLayoutInfo.kt`](../androidApp/src/main/java/com/example/imagefeed/android/adaptive/AdaptiveLayoutInfo.kt) inspects `WindowSizeClass` and `WindowInfoTracker` `FoldingFeature`, while [`AdaptiveUtils.kt`](../androidApp/src/main/java/com/example/imagefeed/android/AdaptiveUtils.kt) reads quantized `LocalPaneWidthDp` (falling back to `LocalAdaptiveLayoutInfo.current.screenWidthDp`) so column counts and Retina CDN widths adapt accurately inside `ListDetailSceneStrategy` panes:
  * Compact width (< 600dp) uses a floating tonal pill hosting M3 Expressive `ShortNavigationBar` (`FloatingBottomNavigationBar` in [`FloatNavigationChrome.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/FloatNavigationChrome.kt), grounded in `surfaceContainerHigh` + `outlineVariant`), switching to collapsible `WideNavigationRail` (`ExpressiveNavigationRail`) with safe-drawing insets and an [`ApertureRandomizeButton`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/ExpressiveShapes.kt) header on Medium/Expanded widths ($\ge 600\text{dp}$).
  * `ListDetailSceneStrategy` (`listPane` + `detailPane` + [`PhotoDetailPlaceholder`](../androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailPlaceholder.kt)) activates dual-pane layouts on wide screens and Book/TableTop foldable postures while avoiding hinge creases.

### Material 3 Design, Surface Hierarchy & Motion
* **Design System Package (`designsystem/`)**: Implements the **Matte → Satin → Float** surface grammar via [`SurfaceTokens.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/SurfaceTokens.kt) (`MatteSurface`), [`SatinHeaderScaffold.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/SatinHeaderScaffold.kt) (edge-to-edge top-bar scaffold with `LocalSatinHeaderPadding`, `SatinPullToRefreshBox`, and draw-phase `Modifier.satinProgressiveBlur` on API 33+ degrading to a multi-stop `surface` scrim on API 29–32 and reduced motion), [`SharedTransitionLocals.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/SharedTransitionLocals.kt) (`LocalAppSharedTransition` retiring manual scope parameter threading, plus `SatinOcclusionController` suppressing Satin blur while a returning source card intersects the header and feathering blur back in over `550ms` after transition settlement), [`FloatNavigationChrome.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/FloatNavigationChrome.kt) (`FloatingBottomNavigationBar`, `ExpressiveNavigationRail`), and [`ExpressiveShapes.kt`](../androidApp/src/main/java/com/example/imagefeed/android/designsystem/ExpressiveShapes.kt) (`PolygonShape`, `MorphPolygonShape`, `ApertureRandomizeButton`).
* **Edge-to-Edge Satin Headers & Micro-Morphs**: All 6 scrollable screens (`FeedScreen`, `CollectionsFeedScreen`, `CollectionDetailScreen`, `FavoritesScreen`, `SearchScreen`, `UserProfileScreen`) draw masonry grids edge-to-edge beneath `SatinHeaderScaffold` with quick-return compact bars (`FeedScreen` topic strip and `SearchScreen` color dial/tabs collapse via layout-phase reads; `CollectionDetailScreen` top bar fades continuously with scroll and animates its cover backdrop blur across `col_cover_*`; `SearchScreen` applies `SearchBarDefaults.windowInsets` to its `topBar` container with `widthIn(max = 720.dp)` and `fillMaxWidth()` `InputField` parity for `ExpandedDockedSearchBar`, while [`MainActivity.kt`](../androidApp/src/main/java/com/example/imagefeed/android/MainActivity.kt) consumes `WindowInsetsSides.Start` on the rail sibling `Scaffold` so rail layouts do not double-pad start cutouts). Photographer avatars transition continuously via `sharedElement` (`avatar_${username}`) into `UserProfileScreen`, `FeedScreen` uses `ApertureRandomizeButton`, `FavoritesScreen` frames its empty-state icon in `ExpressiveShapeTokens.SoftScallopShape`, and `SearchColorDial` morphs the active swatch between `CircleShape` and `SquirclePolygon`.
* **Immersive Photo Details, Compact Zoom & Floating Toolbar**: [`PhotoDetailsScreen.kt`](../androidApp/src/main/java/com/example/imagefeed/android/PhotoDetailsScreen.kt) floats a transparent Satin `CenterAlignedTopAppBar` edge-to-edge via `SatinHeaderScaffold` over an ambient `photo.color` canvas (`derivePhotoAmbientTint`). [`PhotoCanvasPane.kt`](../androidApp/src/main/java/com/example/imagefeed/android/details/PhotoCanvasPane.kt) enables `1.0x–4.0x` pinch-to-zoom (`transformable` with clamped pan bounds) and `1.0x ↔ 2.5x` double-tap zoom on both compact phones and dual-pane layouts, yielding vertical scroll cleanly to parent `verticalScroll` at `1.0x`, disabling progressive blur while zoomed, and linking photographer avatars (`avatar_${username}` via `LocalAppSharedTransition`) from both canvas and [`PhotoInspectorPane.kt`](../androidApp/src/main/java/com/example/imagefeed/android/details/PhotoInspectorPane.kt) into `UserProfileScreen`. [`PhotoActionToolbar.kt`](../androidApp/src/main/java/com/example/imagefeed/android/details/PhotoActionToolbar.kt) uses Material 3 1.5.0 `HorizontalFloatingToolbar` (`FloatingToolbarDefaults.exitAlwaysScrollBehavior` + `vibrantFloatingToolbarColors()`) with Full/RAW tracked downloads, Share intent, and a `CircleShape` ↔ rounded-squircle `MorphPolygonShape` Bookmark toggle.
* **Expressive Theme, Physics Motion & Polygon Controls**: `ImageFeedTheme` in [`Theme.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Theme.kt) uses `MaterialExpressiveTheme` with `MotionScheme.expressive()`, and `NavDisplay` transitions in [`MainActivity.kt`](../androidApp/src/main/java/com/example/imagefeed/android/MainActivity.kt) are driven by `MaterialTheme.motionScheme` springs (`defaultSpatialSpec`, `defaultEffectsSpec`, `fastEffectsSpec`) while preserving directional `NavigationEvent.EDGE_LEFT` predictive-back motion. [`ExpressiveShapeTokens`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Shape.kt) (`PolygonShape` / `MorphPolygonShape`) are reserved strictly for micro-controls, badges, and empty-state backdrops (`ApertureRandomizeButton`, `PhotoDetailPlaceholder` soft-scallop container, `PhotoActionToolbar` bookmark toggle); photographs are never clipped into polygons.
* **Matte Card & Token Hygiene**: [`PhotoCard.kt`](../androidApp/src/main/java/com/example/imagefeed/android/components/PhotoCard.kt) uses a compact Matte corner attribution capsule (`SurfaceTokens.matteScrimPillColor()` + `outlineVariant` border, zero live blur) in place of full-width bottom scrims, and discovery tiles (`TopicCapsuleCard`, [`SearchDiscoveryView.kt`](../androidApp/src/main/java/com/example/imagefeed/android/search/SearchDiscoveryView.kt)) use semantic `MaterialTheme.colorScheme` Matte tokens across Light and Dark themes.
* **Color Palettes & Screen Subpackages**: Dynamic tonal color palettes and semantic surface container tokens are defined in [`Theme.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Theme.kt), [`PhotoThemePalette.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/PhotoThemePalette.kt) (delegating hex parsing, HSL conversion, and tonal swatch derivation directly to `:core:model`'s `PhotoColorEngine`), [`Color.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Color.kt), [`Shape.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Shape.kt), and [`Type.kt`](../androidApp/src/main/java/com/example/imagefeed/android/theme/Type.kt), while detail, search, profile, and shared card UIs live in cohesive `details/`, `search/`, `profile/`, and `components/` subpackages.
* Hero photo transitions wrap navigation sections in `SharedTransitionLayout` paired with `LocalNavAnimatedContentScope`, plus predictive back support via `androidx.navigationevent.compose`.

## 2. Apple (`iosApp` & `macosApp`): Liquid Glass Design System & Multi-Target UI

### Shared Apple Source Tree
* Both the `iosApp` (iOS 17+) and `macosApp` (macOS 14+) targets compile the same SwiftUI codebase under `iosApp/iosApp/` configured in [`iosApp/project.yml`](../iosApp/project.yml).
* Any edit to `iosApp/iosApp/**` must conditionally handle `#if os(iOS)` / `#elseif os(macOS)` differences (`UIKit` vs. `AppKit`, `UIScreen` vs. `NSScreen`, `UIScrollView` vs. `NSScrollView`) and build cleanly on both Xcode schemes after running `xcodegen generate --spec iosApp/project.yml`.

### Tiered Apple DesignSystem (`Matte → Satin → Float`)
* `iosApp/iosApp/DesignSystem/` modularizes Apple UI tokens and shared components:
  * [`SurfaceTokens.swift`](../iosApp/iosApp/DesignSystem/SurfaceTokens.swift) — Centralizes `GlassTheme` tokens, WCAG AAA dark scrim (`highContrastScrimColor`), semantic Light/Dark tokens (`canvasBackgroundColor`, `surfaceBackgroundColor`, `subtleFillColor`, `activePillFillColor`, `activePillForegroundColor`, `matteBorderColor`), `.matteSurface()` / `.matteCapsule()` (tonal fill + 0.5pt hairline border, zero backdrop blur), `.satinScrollEdge(ignoresTopSafeArea:)` (OS 26+ `.scrollEdgeEffectStyle(.soft, for: .top)` + OS 17–25 / 14–25 top canvas-color gradient fade) & `.satinNavigationBar()`, OS-gated `.floatGlass()` (background-layered `.glassEffect(.regular.interactive(), in:)` preserving child contrast), and `.glassBackground(...)`.
  * [`PlatformToolbarButton.swift`](../iosApp/iosApp/DesignSystem/PlatformToolbarButton.swift) — Native SwiftUI `Button`/`Label` inside `.toolbar` on macOS (and iOS 26+), with tactile circular `GlassToolbarButton` orb fallback on iOS 17–25 and `PhotoDetailsView` overlays.
  * [`MacOSHorizontalScrollBridge.swift`](../iosApp/iosApp/DesignSystem/MacOSHorizontalScrollBridge.swift) — Isolates `MacOSHorizontalScrollCoordinator` and AppKit `NSEvent` wheel monitoring.
  * [`PhotoGridCard.swift`](../iosApp/iosApp/DesignSystem/PhotoGridCard.swift) — Unified configurable masonry photo card used across [`PhotosFeedView.swift`](../iosApp/iosApp/PhotosFeedView.swift), [`FavoritesView.swift`](../iosApp/iosApp/FavoritesView.swift), [`SearchView.swift`](../iosApp/iosApp/SearchView.swift), [`CollectionDetailView.swift`](../iosApp/iosApp/CollectionDetailView.swift), and [`UserProfileView.swift`](../iosApp/iosApp/UserProfileView.swift) with `GlassStyle.lightweight` attribution pills, `NavigationPreviewSeeder` Frame-0 cache seeding, iOS 18+ `.matchedTransitionSource` photo (`photo-\(id)`) and avatar (`user-\(username)`) sources, and context menu support.
  * [`PlatformNavigationShell.swift`](../iosApp/iosApp/DesignSystem/PlatformNavigationShell.swift) and [`AppNavigation.swift`](../iosApp/iosApp/DesignSystem/AppNavigation.swift) — Root navigation shell (`AppRootTab`, `NativeLiquidGlassTabShell`, `LegacyFloatingTabShell`, `adaptiveTabBarVisibility()`, `openRootSearch`, `searchFocusTrigger`), unified `AppRoute` (`photo`, `collection`, `user`, `search`), `NavigationPreviewSeeder`, `heroNamespace` environment key, and `.appNavigationDestinations(...)` wiring iOS 18+ `.navigationTransition(.zoom)` and brisk macOS `NavigationStack` transitions.
* **Tiered Performance Policy**:
  * Elevated navigation chrome ([`FloatingTabCapsule.swift`](../iosApp/iosApp/FloatingTabCapsule.swift), `FeedCategoryBar`, `SearchTabBar`, detail action orbs) uses live blur styles (`.ultraThin` / `.regular`) with specular hairline borders.
  * High-frequency masonry overlays (photographer attribution pills) use `GlassStyle.lightweight` (single-pass translucent dark scrim + specular border, `hasShadow: false`), while [`CollectionMosaicCard`](../iosApp/iosApp/CollectionsFeedView.swift), [`UserCardView`](../iosApp/iosApp/SearchView.swift), [`InsightsView`](../iosApp/iosApp/UserProfileView.swift) charts, and [`PhotoInspectorView`](../iosApp/iosApp/PhotoInspectorView.swift) interior cards/tag pills use zero-blur `.matteSurface()` / `.matteCapsule()`.
* **Accessibility Fallbacks**: `MatteSurfaceModifier`, `GlassBackgroundModifier`, and `FloatingTabCapsule` automatically fall back to solid semantic surfaces (`fallbackBackgroundColor`) and crisp `fallbackBorderColor` borders when `@Environment(\.accessibilityReduceTransparency)` or `@Environment(\.colorSchemeContrast) == .increased` is active.

### Apple Navigation & Layout Ergonomics
* **Container-Aware Adaptive Layout**: [`AdaptiveLayoutHelper.swift`](../iosApp/iosApp/AdaptiveLayoutHelper.swift) measures quantized pane width via `.measureContainerWidth($containerWidth)` (`.onGeometryChange` on iOS 18+ / macOS 15+, `PreferenceKey` fallback on iOS 17 / macOS 14) and propagates `\.containerWidth`, dynamically computing `2–5` photo columns, `1–3` collection columns, and Retina CDN pixel widths across iPhone, iPad Split View, and resizable macOS windows.
* **iOS Shell**: [`ContentView.swift`](../iosApp/iosApp/ContentView.swift) delegates to [`PlatformNavigationShell.swift`](../iosApp/iosApp/DesignSystem/PlatformNavigationShell.swift) for 4-destination parity (`Photos` | `Collections` | `Favorites` | `Search`):
  * On **iOS 26+** (`#available(iOS 26.0, *)`), `NativeLiquidGlassTabShell` renders Apple's native refractive Liquid Glass `TabView` with `.tabBarMinimizeBehavior(.onScrollDown)` and `Tab(role: .search)` hosting `SearchTabView`, retiring `CapsuleScrollCoordinator` scroll-offset overhead. It drives `.toolbarVisibility(isTabBarVisible ? .visible : .hidden, for: .tabBar)` directly at each `Tab` root from `ContentView.isCapsuleVisible` while `adaptiveTabBarVisibility(hideOnModernOS:)` only hides on iOS 26+ when `hideOnModernOS` is `true`, ensuring pushed routes (`PhotoDetailsView` after dismissing the inspector sheet, `CollectionDetailView`, `UserProfileView`) never retain minimized tab bar orbs.
  * On **iOS 17–25**, `LegacyFloatingTabShell` isolates `UITabBar` suppression, `CapsuleScrollCoordinator`, and the 4-tab [`FloatingTabCapsule.swift`](../iosApp/iosApp/FloatingTabCapsule.swift) fallback (with `accessibilityReduceTransparency` and `colorSchemeContrast == .increased` fallbacks).
  * [`PhotosFeedView.swift`](../iosApp/iosApp/PhotosFeedView.swift) (`PhotosFeedTabView`, `FeedCategoryBar` with `.floatGlass` & `.symbolEffect(.bounce)` Shuffle trigger, `CategoryTabButton`) and [`FavoritesView.swift`](../iosApp/iosApp/FavoritesView.swift) (`FavoritesTabView` reusing `PhotoGridCard` with destructive `"Remove Bookmark"` context menus) route via unified `AppRoute` + `.appNavigationDestinations(...)`, retiring `selectedPhotoForHero` `ZStack` overlays on iOS 18+ and macOS while preserving the `#unavailable(iOS 18.0)` overlay fallback on iOS 17; `CollectionsFeedTabView` `onSearchClick` and `⌘F` route cleanly via `openRootSearch` + `searchFocusTrigger` to the root `Search` tab.
* **macOS Shell**: [`MacOSContentView.swift`](../iosApp/iosApp/MacOSContentView.swift) uses `NavigationSplitView` sidebar navigation (`Photos`, `Collections`, `Favorites`, `Search` hosting `SearchTabView`), window-level `⌘F` (focusing `SearchView`'s `.searchable(..., isPresented:)` via `openRootSearch` / `searchFocusTrigger` without opening nested search stacks), `⌘S` shuffle, persistent non-collapsing `FeedCategoryBar` / `SearchTabBar`, and horizontal mouse-wheel delta translation + chevron buttons (`chevron.backward` / `chevron.forward`) on horizontal category/tab strips.
* **Satin Scroll Edges & Full-Bleed Floating Bars**: All 6 scrollable Apple views (`PhotosFeedView`, `CollectionsFeedView`, `CollectionDetailView`, `FavoritesView`, `SearchView`, `UserProfileView`) adopt `.satinNavigationBar()` + `.satinScrollEdge()` (iOS/macOS 26+ `.scrollEdgeEffectStyle(.soft, for: .top)` without `.toolbarBackground(.visible)` double-bar seams, and a zero-blur canvas-color top gradient fade on OS 17–25 / 14–25). `FeedCategoryBar` (`PhotosFeedView.swift`) and `SearchTabBar` ([`SearchView.swift`](../iosApp/iosApp/SearchView.swift)) dock via `.safeAreaInset(edge: .top, spacing: 0)` inside `44pt` `.floatGlass(shape: Capsule())` capsules with `CategoryTabButton` `matchedGeometryEffect` selection pills and `.sensoryFeedback(.selection, trigger:)`.
* **Photo Details, Zoom & Avatar Continuity**: On iOS 18+, all 5 photo grids (`PhotosFeedView`, `CollectionsFeedView`/`CollectionDetailView`, `FavoritesView`, `SearchView`, `UserProfileView`), photographer avatars (`PhotoGridCard`, `SearchView` `UserCardView`, `CollectionDetailView` curator avatar), and [`PhotoDetailsView.swift`](../iosApp/iosApp/PhotoDetailsView.swift) detail attribution avatars wire `.matchedTransitionSource` (`photo-\(id)` with `12pt` corner radius and `user-\(username)`) into `.navigationTransition(.zoom)` destinations inside [`AppNavigation.swift`](../iosApp/iosApp/DesignSystem/AppNavigation.swift). `NavigationPreviewSeeder` populates `MetroHelper.shared` `NavigationPreviewCache` across all entry points (including `FeedViewModel.fetchRandomPhotoId`), and [`PhotoDetailsView.swift`](../iosApp/iosApp/PhotoDetailsView.swift) accepts `initialPhoto: Photo?` so the canvas renders on Frame 0 while `PhotoDetailsViewModel` loads lazily in `.task`, pairing explicit-toggle bookmark haptics (`favoriteFeedbackTrigger`) and `GlassToastPill` feedback with bookmark and copy-to-clipboard actions. `ZoomablePhotoCanvas` delivers `1.0x–4.0x` `MagnifyGesture` + pan + double-tap zoom across both iPhone compact and iPad/macOS dual-pane layouts; macOS replaces `.padding(.top, 60)` overlay back buttons with `.toolbar` `PlatformToolbarButton` and `Escape` dismissal; and OS 26+ wraps co-located floating controls (`compactFloatingBar`, top orbs, `GlassToastPill`) in `GlassEffectContainer` + `.glassEffectID` with SF Symbol `.replace`/`.bounce` effects. iOS compact layout presents [`PhotoInspectorView.swift`](../iosApp/iosApp/PhotoInspectorView.swift) in a non-modal detented bottom sheet, while iPad/macOS renders a side-by-side dual pane; inside `PhotoInspectorView`, all nested cards and tag pills use zero-blur `.matteSurface()` / `.matteCapsule()`, rendering a 2×2 / 4-column EXIF Bento Grid, interactive `:core:model` `PhotoColorEngine` tonal swatches (tap-to-copy + toast + haptic), tracked Full/RAW split downloads, and photo-hue-accented `HistoricalStatsChart`, bookmark highlights, and `MapCardView` pins.

## 3. Ephemeral Cross-Platform UI Visual Review

* **Before / After Visual Review Gate & Progressive Readiness**: UI changes follow [`.agents/skills/ui-visual-review/SKILL.md`](../.agents/skills/ui-visual-review/SKILL.md), writing ephemeral PNGs exclusively into the session artifact directory (zero Git-committed binaries) using offline fixtures ([`UiPreviewFixtures.kt`](../androidApp/src/main/java/com/example/imagefeed/android/preview/UiPreviewFixtures.kt), [`UIPreviewFixtures.swift`](../iosApp/iosApp/UIPreviewFixtures.swift)). Screens are made preview/snapshot-ready progressively as specs touch them (pilot baseline: Photo Details).
* **Android**: Stateless `*ScreenContent` / `@Preview` composables rendered through the **Antigravity Compose Preview Sidecar**.
* **Apple (`iosApp` / `macosApp`)**: Two-tier capture—**Mode A** fast `UIHostingController`/`NSHostingView` snapshot tests ([`UIVisualSnapshotTests.swift`](../iosApp/iosAppTests/UIVisualSnapshotTests.swift)) for layout/tokens/themes, and **Mode B** full window-server capture ([`UIWindowServerSnapshotUITests.swift`](../iosApp/iosAppUITests/UIWindowServerSnapshotUITests.swift) + Xcode `RenderPreview`) for `.ultraThinMaterial` glass blurs, floating bars, and sheets.
